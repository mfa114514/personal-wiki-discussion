# 个人 Wiki：发展讨论资料

这是为一次只读研究与讨论整理的资料快照，整理日期为 2026-10-05。这里以已有代码、材料和实验记录为主，并补充当前背景与十条讨论命题。用户希望与一个能阅读项目、但不实际操作文件的 AI 反复交流，形成可实行的发展方案；方案可以包含多个选项和需要用户判断的地方。

2. 阅读[十条讨论命题](讨论命题.md)。它们是讨论入口，可以调整、合并或拆分。
3. 阅读[梯度下降逐步融合试验](资料/knowledge-maintenance/tasks/2026-10-02-wiki-flow/逐步融合试验/README.md)，按五个输入与五个版本观察内容怎样发展。这是用户认可总体方式的实质案例。
4. 阅读[当前出链说明](资料/knowledge-maintenance/output/正文词条出链说明.md)和[小知识库信息流实验](资料/knowledge-maintenance/tasks/2026-10-02-wiki-flow/README.md)，结合其中的原文与旧稿判断设计。
5. 按讨论需要再查看下面的代码入口、早期实验和更多课程材料，无需首先通读所有资料。

## 项目的目标与使用情境

整个本地文件区域将逐渐成为用户自己的 Wiki。用户和 AI 都参与维护，也都用它学习、理解和查找；以后可能有其他读者。内容可以是论文、网页、转写文字、课程资料、普通笔记、代码，以及其他值得保存的东西。怎样进入知识库不是当前主线，也不要求用户在白天主动整理一遍。

设想的日常周期是：用户白天学习、研究、阅读和写作，正常增删改文件；夜间维护系统识别变化，理解材料，建立链接、完善词条并交付结果；第二天用户查看重要修改、处理建议，然后继续工作。用户也可能在维护前补充方向或具体任务。

低阻力是贯穿使用和建设的原则。机械且可恢复的工作尽量自动完成，重要语义改动保持可审阅；不让用户为了维护系统而频繁填写属性、整理目录或逐项批准链接。先在小范围跑通，再按真实需求扩大。

知识主体优先使用本地普通文件，尤其是 Markdown；其他格式自然保留。Obsidian 是现有人工阅读与编辑界面。Git/GitHub 已用于小范围试点，但整库范围、同步方式和夜间流程尚未确定。缓存、索引或以后引入的数据库应是可以重建的派生内容。复杂 RAG、云服务、完整 Agent 系统等不是第一版的前提。

## 最新认识及需要保持的边界

- 词条应有自己的主题、逻辑和实质讲解，能帮助学习与复习。结构、深度和篇幅随内容决定，不把相关概念列表当成正文，也不把所有词条写成同一模板。
- 当前已停止“首次建立就写得完善”的初始化路线。相关材料逐次出现，用已有内容与当次材料融合形成下一版；可以局部补充、新开一个方面、重组、说明冲突，也可以不改。不是把摘录依次追加在后面。
- 当前试验的新增信息来自实际引入的笔记。“笔记”在这里包括实验中读取的课程材料；更广来源如何读取仍可以讨论。词条之间可以互相链接，但不互相作为新增内容来源，不因链接出现而递归生成内容。
- 同一段材料可以帮助多个词条，各页围绕自身主题吸收和讲述，不能简单复制相同解释。直接相关与较近关联值得考虑，较远内容结合价值取舍；关系远近不是固定层数。
- 出链先根据文档的解释价值选择概念，再判断页面终点。目标可以暂不存在；判断终点要看含义、范围和完全同义的别名，不能只看同名。
- 已选概念在正文多次出现时，指向同一页面；显示词可以不同于页面名。原文没有适合直接标注的文字时，在对应段落或内容块附近集中列出补充链接，不能妨碍正常阅读。
- 正向概念链接到独立页面；反向查阅可以到来源中的具体文字。出链不意味着立刻建立全部目标页，此前“五个”的数量限制已撤销。
- 正文以中文为主，专业英文首次出现适当解释。段落、必要列表和公式以好读为目的；数学使用 Obsidian 的行内 $...$ 与行间 $$...$$。不机械规定行数、字数或每页栏目。
- 词条如何体现周围材料的影响，不能只理解为附加反链列表或成长日志。用户希望正文随着相关内容增加而变化；相关材料如何呈现、其他知识文件形式如何组织仍在讨论。
- 现有项目 output 是用户点名收录的成果目录，不能自动放入报告或草稿。本资料库是另一个任务的快照，不增加原 output 的文件。

这些是目前讨论背景，不是封闭的终局规则。十条命题也不是已经采纳的设计方案。

## 讨论怎样形成交付

先读事实，再提出可行方案；每个重要选择说明实际使用方式、维护成本、与现有实验的关系，以及仍需要用户判断的地方。用户不希望死板遵守描述性例子，应深入理解目的，并用具体情况说明取舍。

允许保留两种或多种方案，但要说明差异和适用情境，以及用什么小实验能帮助选择。可以质疑已有设计和代码，不默认它们正确，也不无理由重建整个系统。

最终应形成一份能指导后续实施的第一版发展方案，区分现有事实、已认可认识、新提议和待决定事项。可以保留讨论中的变化与分歧。一次只读研究无法证明方案已经运行可用，后续验证办法应写清楚。

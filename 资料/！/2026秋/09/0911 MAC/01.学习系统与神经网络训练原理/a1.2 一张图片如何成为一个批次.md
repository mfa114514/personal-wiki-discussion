## 1. 这一轮要交给模型的到底是什么

第一章把监督学习数据写成：

$$
\mathcal D=\{(\mathbf x_i,y_i)\}_{i=1}^{N}
$$

在这里，$i$ 标识样本，$N$ 是样本总数，$\mathbf x_i$ 是输入，$y_i$ 是对应的真实类别。

Fashion-MNIST（服饰图片数据集）已经提供图片和标签。每张图像有 $28\times28$ 个灰度像素，类别编号为 $0,1,\ldots,9$。例如编号 9 表示短靴。这些整数是类别的标识，不表示“短靴比其他类别数值更大”。中英文名称可以查 [类别表](../../data/classes.csv)。

本轮使用官方训练部分的 60,000 条数据，从中划出 50,000 条用于训练、10,000 条用于验证。另有官方测试部分 10,000 条，本轮的脚本不会读取它。

本轮要为训练过程准备两个对象：

$$
\mathbf X\in\mathbb R^{B\times784},\qquad
\mathbf y\in\{0,\ldots,9\}^{B}
$$

其中 $B$ 是一个批次的样本数，$784=28\times28$ 是展平后一张图片的特征数。$\mathbf X$ 输入模型，$\mathbf y$ 用于将模型输出与真实类别比较、计算损失。$\mathbf X$ 的每一行与 $\mathbf y$ 的同一个位置必须对应同一张图。这个对应关系要贯穿读取、划分和打乱过程。

## 3. 原始像素、图片对象和模型输入张量

继续检查数据内部的整数数组：

```python
print(raw_dataset.data.shape)
print(raw_dataset.data.dtype)
print(raw_dataset.targets.shape)
```

本实现的 `.data` 保存原始图片数组，`.targets` 保存所有标签。你应看到：

```text
torch.Size([60000, 28, 28])
torch.uint8
torch.Size([60000])
```

`dtype` 表示数据类型。`uint8` 是 8 位无符号整数，可以表示 0—255。对于这些灰度图，每个整数表示一个像素的亮度。

注意：整份内部数组本来就是张量，不等于 `raw_dataset[0]` 返回的图片也是张量。数据集的取样接口还会把内部数组组织成图像对象，并在需要时执行转换。**存储形式与取样接口的返回形式可以不同。** `.data` 和 `.targets` 是这个具体数据集实现提供的属性，不要求所有 Dataset 都具备同名属性。

把刚才取出的图像转为模型更适合使用的形式：

```python
to_tensor = transforms.ToTensor()
image_tensor = to_tensor(image)
print(image_tensor.shape)
print(image_tensor.dtype)
print(image_tensor.min().item(), image_tensor.max().item())
```

第一行创建一个转换工具，第二行用它处理 `image`。对于本数据集这样的 8 位灰度图片，`ToTensor` 做了两项关键工作：得到按“通道、高、宽”组织的浮点张量，并把原始像素除以 255。因此你应看到形状 `[1, 28, 28]`、类型 `torch.float32`；本地第 0 张图的最小、最大值为 `0.0`、`1.0`。[ToTensor 官方说明](https://docs.pytorch.org/vision/0.25/generated/torchvision.transforms.ToTensor.html)

这里的 1 是 **channel（通道）**数：灰度图每个像素只有一个亮度分量。它不是批量维度，因为当前只有一张图像，尚未组批。`float32` 表示以 32 位浮点数保存数值；它能表示小数。`min()`、`max()` 求最小值和最大值，`.item()` 把仅含一个数的张量取成普通 Python 数值，便于显示或记录。

设原始像素整数为 $a_{i,r,c}$，其中 $i$ 是样本编号，$r,c$ 分别是行、列位置。转换后图像张量记为 $\mathbf I_i$：

$$
(\mathbf I_i)_{0,r,c}=\frac{a_{i,r,c}}{255},\qquad
\mathbf I_i\in[0,1]^{1\times28\times28}
$$

这是固定的像素缩放：改变数值尺度，保留像素的位置关系。它没有从所有图片中估计任何均值或方差。如果后面改用需要估计统计量的预处理，就应只用训练部分估计，再应用到验证和测试数据，避免使用后两者的信息影响训练流程。

类别标签不做这个除以 255 的转换，也不把它当成连续数值预测目标。这里的标签仍表示十个离散类别之一。

## 4. 让每次取样自动执行同一个转换

如果每次都手动写 `to_tensor(image)`，很容易在不同地方漏掉预处理。我们把转换交给数据集对象：

```python
dataset = datasets.FashionMNIST(
    root="data/raw",
    train=True,
    transform=transforms.ToTensor(),
    download=False,
)

x, y = dataset[0]
print(x.shape, x.dtype)
print(y, type(y))
```

现在 `dataset[0]` 的执行链是：找到第 0 张图片和标签 → 对图片执行配置的转换 → 返回转换后的图片和原标签。`x` 的形状为 `[1, 28, 28]`，`y` 仍是 Python 整数 9。

这个转换是在取样时执行的。设置 `transform=...` 不会把原始文件改成浮点图片，也不会把整份数据立刻组织成一个训练批次。

这对应第一章的一个重要工程位置：**预处理位于原始数据与模型输入之间。** 后续训练和推理必须约定相同的输入含义。训练时输入 0—1 的数值、推理时却直接输入 0—255 的数值，就改变了模型接收的数据尺度。

## 5. 固定哪些样本参加训练，哪些样本用于验证

官方的 60,000 条训练数据，在课程项目中还需要进一步分工。我们选定每类 5,000 条作为训练数据、1,000 条作为验证数据，总数分别为 50,000 和 10,000。这种按类别保留比例的划分叫 **stratified split（分层划分）**。

训练部分用于计算梯度、更新参数；验证部分用于观察模型在未参加参数更新的样本上表现如何，并帮助选择设置。官方测试部分留到方案固定后做最终评估。若根据测试结果反复调参，测试信息也就参与了方案选择，难以再代表最后一次独立评估。

官方训练部分每类恰有 6,000 条，可以按类别独立抽取。训练索引集合记为 $I_{\mathrm{train}}$，验证索引集合记为 $I_{\mathrm{val}}$。它们应满足：

$$
|I_{\mathrm{train}}|=50000,\quad |I_{\mathrm{val}}|=10000,\quad
I_{\mathrm{train}}\cap I_{\mathrm{val}}=\varnothing
$$

并且合起来覆盖原始索引 $\{0,\ldots,59999\}$。这里保存索引就够了，不必复制两套图片文件。

配套脚本第 3 段的核心代码如下。这里是在解释脚本；若要在交互解释器中复现，要先有上一节的 `dataset`，并保持代码中的缩进，循环结束后输入一个空行：

```python
SPLIT_SEED = 42
VAL_PER_CLASS = 1000
split_generator = torch.Generator().manual_seed(SPLIT_SEED)
train_indices = []
val_indices = []

for class_id in range(10):
    class_indices = torch.where(dataset.targets == class_id)[0]
    permutation = torch.randperm(len(class_indices), generator=split_generator)
    shuffled_indices = class_indices[permutation]
    val_indices.extend(shuffled_indices[:VAL_PER_CLASS].tolist())
    train_indices.extend(shuffled_indices[VAL_PER_CLASS:].tolist())
```

这段代码每轮只处理一个类别，过程是：找出该类在原始数据中的位置 → 打乱这些位置 → 前 1,000 个位置留作验证 → 剩余位置用于训练。

逐步看这些新写法：

- `[]` 创建空列表，用来逐步收集索引。`range(10)` 依次给出 0 到 9；`for` 后的冒号与缩进标明需要对每个类别重复执行的代码。
- `dataset.targets == class_id` 逐个判断标签是否属于这个类别，得到真假值组成的张量。`torch.where(...)[0]` 取出这些真值所在的一维位置，也就是样本索引。
- `torch.randperm(n)` 给出 0 到 $n-1$ 的随机排列。`class_indices[permutation]` 用这个排列重新取索引，因此改的是取样顺序，没有把图片和标签拆开打乱。
- `[:1000]` 表示前 1,000 项，不含位置 1000；`[1000:]` 表示从位置 1000 一直到末尾。`.tolist()` 转成 Python 列表，`.extend(...)` 把其中各项接到已有列表末尾。

`torch.Generator()` 创建一个专用的随机数发生器，`manual_seed(42)` 设置 **random seed（随机种子）**。计算机这里使用伪随机序列：在相同实现和相同调用顺序下，从同一个种子开始，可以重现相同的序列。42 只是一个固定选择，不会让划分更优。

在这个项目中，我们还会保存实际索引。以后复用保存的结果，比每次凭记忆重新运行一套划分流程更直接。

得到两个列表后，实际构造子集只需要：

```python

train_dataset = Subset(dataset, train_indices)
```

`Subset` 表示按索引访问原数据集的子集。具体来说：

## 7. DataLoader 把单个样本组织成批次

**DataLoader（数据加载器）**负责按指定顺序取样，并将样本组合成 **mini-batch（小批次）**。它利用数据集的取样接口，所以刚才配置的图片转换仍会生效。

脚本为训练数据配置：

```python
from torch.utils.data import DataLoader

BATCH_SIZE = 64
SHUFFLE_SEED = 123
order_generator = torch.Generator().manual_seed(SHUFFLE_SEED)

train_loader = DataLoader(
    train_dataset,
    batch_size=BATCH_SIZE,
    shuffle=True,
    generator=order_generator,
    num_workers=0,
    drop_last=False,
)
```

`batch_size=64` 表示通常一次取 64 个样本；`shuffle=True` 表示打乱取样顺序。`num_workers=0` 表示在当前进程中读取，先不创建额外的数据读取进程；`drop_last=False` 表示保留不足 64 个样本的最后一批。

这次的 `order_generator` 只控制组批过程使用的随机序列，与划分时的 `split_generator` 分开。改变 `SHUFFLE_SEED`，就可以观察不同取样顺序，而不改变训练和验证的成员。

验证加载器使用同样的批量大小，但设置 `shuffle=False`。验证时通常只需依次遍历所有样本并汇总结果，固定顺序也便于对照。参数含义和默认组批行为可查 [PyTorch 数据加载说明](https://docs.pytorch.org/docs/2.10/data.html)。

实际取出第一批：

```python
train_iterator = iter(train_loader)
images, labels = next(train_iterator)
print(images.shape, images.dtype, images.device)
print(labels.shape, labels.dtype)
print(labels[:8])
```

`iter(...)` 创建 **iterator（迭代器）**，可以理解成一次遍历中记录“取到哪里”的对象。`next(...)` 从它取出下一项，这里的一项就是一个批次。继续调用 `next(train_iterator)` 会继续往后取；每次重新写 `iter(train_loader)` 则开启新的遍历，不能用来代替沿同一次遍历不断前进。

你应该看到图片形状 `[64, 1, 28, 28]`、类型 `torch.float32`、设备 `cpu`；标签形状 `[64]`、类型 `torch.int64`。标签从单样本返回的 Python 整数，组成为一个整数张量。其元素仍是类别编号，没有转成十维独热向量。

图片批次的四个维度依次是：样本数 $B$、通道数 $C$、高度 $H$、宽度 $W$。这里的 $H,W$ 是图像尺寸，暂时不要与下一轮的权重矩阵 $\mathbf W$ 混淆。单个样本的 `[1, 28, 28]` 前面加上批次维度，得到 `[64, 1, 28, 28]`。

在同一环境下重新运行脚本，固定种子可以重现第一批的顺序；但在一个持续运行的训练程序中，随机数发生器状态会不断推进，因此开启下一轮遍历通常会得到新的顺序。不要在每个训练轮次开始时无意中重建同一个种子的发生器，否则会反复使用同一排列。

本轮数据留在 CPU 上。未来训练时，再将当前批次和模型参数放到同一个计算设备上；数据加载器本身不会自动替你申请 GPU 或把全部数据放进显存。

## 8. 批次成为输入矩阵，以及最后一个批次的问题

对多层感知机，我们需要把每张图片展平为长度 784 的向量：

```python
flat_images = images.flatten(start_dim=1)
print(flat_images.shape)
```

`flatten` 表示合并维度。维度编号从 0 开始，`start_dim=1` 表示保留第 0 维的样本数，从第 1 维起把 `1 × 28 × 28` 合并为 784。结果应为 `[64, 784]`。

如果把所有维度一起合并，就会把不同图片也连在一起，失去“每一行一个样本”的结构。现在的对应关系是：

$$
\mathbf I_i\in\mathbb R^{1\times28\times28}
\longrightarrow\mathbf x_i\in\mathbb R^{784}
\longrightarrow
\mathbf X=
\begin{bmatrix}
\mathbf x_1^\top\\\vdots\\\mathbf x_B^\top
\end{bmatrix}
\in\mathbb R^{B\times784}
$$

`labels[i]` 就是 `flat_images[i]` 对应的真实类别。之后模型对每行产生十个类别得分，再结合这些标签计算损失。第一章的小批次目标可以接到这里：

$$
L_{\mathcal B}(\boldsymbol\theta)
=-\frac1B\sum_{i=1}^{B}
\log p_{\boldsymbol\theta}(y_i\mid\mathbf x_i)
$$

其中 $\mathcal B$ 是当前小批次，$\boldsymbol\theta$ 是模型参数，$p_{\boldsymbol\theta}$ 是模型给出的类别条件概率。我们现在准备好了 $\mathbf x_i,y_i$，还没有执行右边的模型概率计算。

接着关注第一章的 **epoch（完整遍历训练集的一轮）**。50,000 个样本、每批 64 个，保留最后不足一批的样本时：

$$
\left\lceil\frac{50000}{64}\right\rceil=782
$$

其中前 781 批各有 64 个样本，最后一批有：

$$
50000-781\times64=16
$$

所以代码不能把每一批都写死成 64 个样本。后续算平均指标时，也不能把含 16 个样本的一批和含 64 个样本的一批直接等权平均，否则每个样本的权重会不同。

脚本通过 `len(train_loader)` 得到批次数，按样本数计算末批大小。它目前只实际取出第一批，显示的末批大小是按配置计算的结果。取出 782 个批次，也不自动等于更新了 782 次参数：只有执行优化器更新才有参数更新；未来使用梯度累积时，两种次数还会进一步分开。

## 9. 运行完整脚本，做两个小对照并保存结果

前面已经拆开解释了数据链条，现在把它作为一个可重复运行的程序执行。**脚本**是保存了 Python 代码的文本文件；Python 从文件顶部开始依次执行。与交互环境相比，文件能把操作步骤保留下来，重新启动后可以再次运行同样的流程。

先确认已经用 `exit()` 离开 Python 的 `>>>`，回到已激活项目 Conda 环境的 Bash，再执行：

```bash
python scripts/inspect_data.py
```

这里的 `python` 后面跟着文件路径，表示执行这份代码文件。脚本里的 `#` 开头行是注释，用于解释代码，不参与计算。

默认设置下，核对以下关键结果：

| 项目 | 预期 |
| --- | --- |
| 训练/验证样本数 | 50,000 / 10,000 |
| 训练集每类数量 | 每类 5,000 |
| 验证集每类数量 | 每类 1,000 |
| 图片批次 | `[64, 1, 28, 28]`，`float32`，CPU |
| 标签批次 | `[64]`，`int64` |
| 展平输入 | `[64, 784]` |
| 训练/验证批次数 | 782 / 157 |
| 根据配置计算的训练末批大小 | 16 |

第一批具体标签的顺序不需要背诵。更重要的是标签范围、图片与标签的对应关系，以及配置相同时能否重复。

第一次完整运行后，将创建固定划分文件，并在 `outputs/` 下建立带日期时间的独立目录。终端最后一行给出实际路径。其中保存：

- `config.json`：这次的批量大小、两个种子和依赖版本等设置。
- `summary.json`：样本数、类别数量、张量形状、前几个标签和划分文件的校验值。
- `samples.png`：本次训练批次前 16 张图片；可以从项目文件列表中找到并打开。

脚本最后的绘图部分使用 Matplotlib（绘图库），把图片放到 4 × 4 的网格中后保存。它选择不需要桌面窗口的绘图方式。`enumerate(...)` 在遍历图格时同时给出位置编号，`imshow(...)` 把像素显示为图像，`savefig(...)` 写入图片文件；这些操作用于查看数据，不参与训练计算。标题使用英文类别名，中英文对应可查类别表。

固定划分的 `split_sha256` 是对文件内容计算的 SHA-256 校验值。本轮用它比较多次运行是否使用了完全相同的划分文件，无需学习校验算法本身。时间戳目录、JSON 保存和图像输出都是为了保留实际操作证据，核心数据处理位于脚本第 2—5 段。

**先做一次不改设置的重复运行。** 再执行同一条命令，应该显示 `loaded`，并产生新的输出目录。两次 `summary.json` 中的划分校验值和前 8 个标签应相同。文件路径不同，说明保留了两次运行；成员与顺序一致，说明当前固定设置可以复现。

**对照一：只改变批量大小。** 用编辑器打开 `scripts/inspect_data.py`，找到开头的 `BATCH_SIZE = 64`，改为 `BATCH_SIZE = 128`，保存文件后再运行。Python 在新的一次运行时会读取修改后的文件。

这次应得到 `[128, 1, 28, 28]`、`[128, 784]`，训练批次数为 391，训练末批大小为 80。训练和验证的成员及类别总数都不应变化，划分校验值也应相同。观察完恢复 `BATCH_SIZE = 64`。

**对照二：只改变取样顺序。** 保持批量大小 64，把 `SHUFFLE_SEED = 123` 改为 `SHUFFLE_SEED = 456`，保存后运行。第一批的样本顺序和样本图通常会变化，但训练/验证成员、每类数量和批次数不变。最后恢复 `SHUFFLE_SEED = 123`，不要改动固定划分的种子或手动编辑索引文件。

如果脚本因划分检查失败而停止，保留已有文件和报错，先核对原因，不删除文件强行重分。如果图片文件没有弹出窗口，这属于预期行为：图已经保存到输出目录，需手动打开。若 CPU 检查程序本身报错，不需要通过申请更多 GPU 来解决。

完成后，把默认运行与两个对照中的关键输出发到聊天即可，也可以像上一轮一样明确反馈全部完成与输出是否符合预期。你应能够说明：训练/验证成员由哪份文件决定，样本顺序由什么控制，为什么 `[64,1,28,28]` 能变为 `[64,784]`，以及为什么最后一批不能假定为 64。

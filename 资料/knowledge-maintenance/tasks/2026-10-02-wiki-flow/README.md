## 继续保留的全局原则

- 低阻力同时用于使用和构建：从实际需要的范围开始，不要求用户先整理输入、维护复杂目录或填写大量属性。
- 内容继续以普通文件为主体，可以来自论文、网页、转录、笔记及其他来源；索引、缓存和状态记录属于可重建的派生数据。
- 用户明确变化识别使用 Git。内容哈希仍可用于历史复制核对，不替代 Git 的变化识别。
- Wiki 通过词条与材料形成关系。先只看当前材料选择值得引出的概念，再结合含义、范围、别名和页面用途判断是否已有终点。
- 维护的正向词条链接从正文到独立页面；反向查阅可以到来源的具体文字。词条讲解围绕概念本身；相关资料与外部参考的具体做法暂缓，当前初始化稿不含这部分。
- 词条讲解围绕主题自身组织，不能以概念关联堆砌代替内容。用户已将“先完成复杂初始化”转为“从当次材料开始，随相关内容逐步融合”；不要求每次增加或大改，变化取决于现有正文与新内容。此前重心与阅读体验的讨论仍可参考，不固定栏目、篇幅或关系层级。别名只收同义表达，正文出链仍按共同方法处理。
- 词条和链接随学习逐渐完善。核心概念选择数量不限制将来正文可标注的链接数量，新词条也可能引出对旧材料的回查。
- 确定、机械且可恢复的工作尽量自动完成；涉及语义、重要改写或位置调整的实际规则共同讨论，避免每天制造大量逐项确认任务。
- 继续列出可修改的计划，区分提案、已确定规则和已执行结果；逐步跑通日常周期，再扩大规模。

## 已确定的流程顺序

用户进一步明确：这一环引出的链接只包括词条。先不看知识库已有内容，只根据当前文档判断哪些概念值得引出；选择完成后才寻找已有终点。有合适终点则连接，没有则新建，然后维护这些词条页。

## 已确定的链接方向与页面分工

用户强调低阻力，并确定：我们维护的正向链接从正文到词条页面；反向查阅可以到来源中的具体文字。因此，被引出的独立概念需要自己的词条页面，不能以另一个页面的小节作为正向链接终点。注意力掩码与因果掩码分别成页；之前询问是否先同页的选项已由本次说明解决。

页面层级与相关性通过内容分工体现。上层词条解释整体概念，在需要处概括并链接到下层词条；下层词条围绕具体概念提供更细的机制、用途与说明。相关但不完全相同的概念分别讲清各自含义和区别。同一个概念的不同名称仍可共用页面，这需要语义判断，不因表面名称不同重复开页。

“更详细”落实为对本页概念的具体展开。各页保持独立可读所需的定义与背景，其他概念的完整展开通过链接查阅；独立开页不要求所有页面具有同样篇幅，也不要求同时写成终稿。词条正文继续面向概念本身，相关材料在单独部分说明其价值。

低阻力的实现提案：反向来源位置与上下文由工具从正文链接派生，随原文变化更新，用户无需手工维护双向链接或段落编号。概念间的层级可先通过正文说明和页面链接表达，暂不要求填写额外层级属性或按目录树安置词条。这两项是实现提案，尚未实现。

## 待讨论的链接选择规则

以下选择标准由 AI 提出，仍供讨论；其中独立页面与链接方向遵守上节已确定规则：

1. 选择值得独立理解、可在其他阅读中复用的概念。模型、机制、运算、任务和基础概念都可以成为词条；不把每个出现的词自动变成一个页面。
2. 结合本文语境说明选择依据：它是正在讲解的对象、读懂本文需要的基础，还是本文明确区分的概念。频率与标题可以提供线索，不能替代这个判断。
3. 保持名称所指含义清楚。例如本文的 token 是文本序列的单位；Q/K/V 是注意力计算中的角色，不能直接按“查询、键、值”三个日常词各建一个通用词条。
4. 按独立概念判断粒度，不按段落或篇幅机械拆分。选中的独立概念各有页面，具体写作深度随概念层级和实际学习增长；不能将小节作为其正向链接终点。
5. 先选择概念，再决定正文标记位置。一个概念可能在本文多次出现，同义名称可以指向同一词条页面；概念数、页面数和正文链接数不必相等。链接密度另在阅读试验中调整。

## 终点识别与词条维护的初步提案

终点判断在概念选择之后进行。名称、别名和搜索可用于找到候选页面，随后必须读取内容，判断含义、范围与页面用途：

- 相关概念只在某页的一节得到讲解：它可作为写作材料，但不能用该节代替独立词条页面；继续识别是否另有合适词条，确认没有则新建。
- 同名异义、只讲邻近概念，或无法可靠确定：继续消歧，不能强行连接或贸然另建同义副本。
